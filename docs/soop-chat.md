# SOOP 채팅 부검

도구 목록 `/apps` → **SOOP 채팅 부검** (`/soop-chat`). 별도 프로그램 설치나 서버 환경 변수 추가 없이 기존 Next.js/Vercel 앱에서 실행합니다.

## 사용

1. 공개 생방송 또는 다시보기의 개별 주소를 입력합니다. 즐겨찾기 목록 주소는 개별 방송 주소가 아니므로 지원하지 않습니다.
2. **채팅 가져오기**를 누릅니다. 다시보기는 SOOP이 제공하는 파일들을 300초 단위로 가져옵니다. 생방송은 페이지가 열린 동안 브라우저에서 수집합니다.
3. 아이디·닉네임·내용 검색, 사용자 선택, 시간 범위(분:초 또는 시:분:초), 메시지 종류 필터를 조합합니다. 모든 메시지 내용은 줄바꿈을 유지해 표시합니다.
4. **검색 결과 CSV**는 현재 필터의 전체 결과를 저장합니다. 화면 페이지 수와 무관합니다. UTF-8 BOM을 포함하며 수식으로 해석될 수 있는 셀은 이스케이프합니다.
5. 이 브라우저의 **저장 기록**에서 다시 열 수 있습니다. 미완료 VOD는 **이어받기**로 성공한 구간을 건너뛰고 재시도합니다.

## 기록 범위와 시간

- 생방송: 연결 이후의 공개 일반 채팅과 OGQ 이모티콘. 수신 시각은 클라이언트 시계 기준이며 작성자의 발신 시각이 아닙니다. 재연결 중 누락은 복구하지 못하며 상태에 표시됩니다. 재연결은 최대 5회입니다. 채팅 전송 기능은 없습니다.
- 다시보기: 공개 XML의 일반 채팅, OGQ 이모티콘, 사용자 ID와 텍스트가 있는 후원 이벤트. 시스템 입퇴장·빈 이벤트는 제외합니다. 이모티콘은 팩/번호 텍스트로 보관합니다.
- 영상 내 시간은 파일별 상대 시간에 앞선 영상 길이를 더합니다. 표시 날짜·시각(KST)은 각 파일 시작 시각을 기준으로 계산한 추정값입니다. 파일 시작 정보가 없으면 시각 미제공으로 표시합니다.
- 같은 사용자의 접속 suffix `(숫자)`를 제거한 ID로 그룹화하되 원본 ID와 각 메시지의 당시 닉네임을 보관합니다. 같은 시간에 같은 내용이 반복돼도 별개 메시지는 보존합니다.
- 비공개·삭제·성인 인증·비밀번호 제한 콘텐츠는 우회하지 않습니다. SOOP의 비공식 조회 형식이 바뀌면 연동 수정이 필요할 수 있습니다.

## 저장 및 배포

- 메시지는 방문자별 IndexedDB에 저장됩니다. 서버 공용 채팅 DB, 다른 방문자와 공유, 탭 종료 후 백그라운드 수집은 없습니다.
- VOD 메타데이터를 서버에서 30초 캐시합니다. 클라이언트는 한 번에 한 구간만 요청하고 실패 시 2회 재시도합니다. 서버는 지정된 SOOP 호스트만 조회하고 리디렉션을 차단하며, 12초/8MB 제한을 적용합니다.
- 인증 쿠키·비밀번호를 요청하거나 저장하지 않습니다. 추가 외부 서비스나 키 설정이 없습니다.
- 브라우저 저장이 차단되거나 용량이 부족하면 경고를 표시하고 메모리의 기록을 CSV로 저장할 수 있습니다. 새 기기/브라우저에서는 기존 기록이 보이지 않습니다.

## 검증

`npm run build`로 프로덕션 빌드합니다. Node 22.18+ 또는 Node 24에서 `node --experimental-strip-types --test tests/chat-inspector.test.mjs`로 URL 허용 목록, 한글/이모지 프레임 분할·결합, ID 통합, 시간 필터, CSV 이스케이프, VOD 파일 시간 보정·경계·중복 보존을 검증합니다.

2026-10-22 예시 VOD 210511423으로 실제 API 통합 검증: 3개 영상 파일, 16개 구간, 메시지 6,765개, ID 846개(일반 채팅 6,706 / 이모티콘 58 / 텍스트 이벤트 1). 생방송 298032215 채팅 서버 입장 및 실제 일반 메시지 수신·파싱도 확인했습니다. 실제 데이터는 저장소에 포함하지 않습니다.

프로토콜 확인 출처: SOOP 플레이어의 공개 클라이언트(`static.sooplive.com/asset/app/liveplayer/player/dist/LivePlayer.js`)와 VOD 메타데이터·채팅 XML. 보조 참고: https://github.com/viijangh2/soopchat . 라이브 프레임은 UTF-8 바이트 길이로 분할하며 `0007`(방송자 상태)은 연결 종료로 처리하지 않습니다.
